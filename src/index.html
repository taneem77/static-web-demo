What is DevOps?

DevOps is a combination of development and operations practices that helps teams build, test, and deliver software faster and more reliably.

Key Principles

  • Automation
  • Continuous Integration
  • Continuous Deployment
  • Continuous Testing
  • Monitoring
  • Collaboration

DevOps Lifecycle

Plan → Code → Build → Test → Release → Deploy → Operate → Monitor

Git & GitHub

Git is a distributed version control system used to track changes in source code.

GitHub is a cloud-based platform that hosts Git repositories and provides collaboration and automation features.

Important Git Commands

  • git clone – Copy a repository locally.
  • git status – Check repository status.
  • git add – Stage changes.
  • git commit – Save changes to Git history.
  • git push – Upload changes to GitHub.
  • git pull – Download latest changes.

CI/CD Pipeline

Continuous Integration (CI) automatically builds and tests the code whenever changes are pushed to the repository.

Continuous Deployment (CD) automatically deploys the updated website after the changes successfully pass the required checks.

Pipeline Flow

Developer → Git → GitHub → GitHub Actions → Test → Deploy → GitHub Pages

Why CI/CD?

  • Find errors early.
  • Automate repetitive tasks.
  • Improve software quality.
  • Deploy changes faster.
  • Reduce manual deployment errors.

Automated Testing

Automated tests verify that the website contains the required files and HTML elements before deployment.

Test Cases

  • Check that index.html exists.
  • Check that style.css exists.
  • Check that the HTML contains a title.
  • Check that the HTML contains an H1 heading.
  • Check that the viewport meta tag exists.

Testing Process

Code Push → Install Dependencies → Run Tests → Test Result

If all tests pass, the deployment stage can continue. If a test fails, deployment is stopped.

GitHub Actions

GitHub Actions is used to automate the CI/CD workflow. The workflow is defined using a YAML configuration file.

Workflow Stages

  1. Checkout the repository.
  2. Set up Node.js.
  3. Install project dependencies.
  4. Run automated test cases.
  5. Deploy the website if tests pass.

Workflow Structure

Push → GitHub Actions → Test → Pass → Deploy

Push → GitHub Actions → Test → Fail → Deployment Stopped

Instructable: GitHub Actions & GitHub Pages

Step 1: Create a GitHub Repository

Create a repository on GitHub and upload the HTML and CSS files.

Step 2: Push the Code

Commit and push the website files to the GitHub repository.

Step 3: Configure GitHub Actions

Create a YAML workflow inside the .github/workflows directory.

Step 4: Add Test Cases

Automated tests are executed to verify that the website is valid before deployment.

Step 5: Deploy using GitHub Pages

After the workflow completes successfully, the website is deployed using GitHub Pages.

Result

New changes pushed to the repository automatically trigger the CI/CD pipeline.
